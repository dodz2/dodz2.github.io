3/20 à 20/20 : sur un agent à outils, le danger n'est pas le chat

Nous avons corrigé notre agent d'exploitation fictif, relancé les mêmes attaques, mesuré. La faille la plus grave se corrige en une demi-journée — à condition de regarder au bon endroit.

Le point de départ

OpsAgent, notre agent d'exploitation fictif, avait 3/20 de résistance :

  • un opérateur se déclarait admin par simple paramètre ;
  • un redémarrage s'exécutait sans confirmation ;
  • un ticket déclenchait des actions tout seul ;
  • des secrets de journal fuitaient en clair, accessibles en lecture seule ;
  • une directive persistait d'un tour à l'autre ;
  • n'importe qui se promouvait admin.

Le modèle, lui, refusait quatre fois sur quatre quand il fallait le convaincre.

Le correctif qui compte

Le réflexe naturel serait de durcir le prompt de l'assistant. C'est inutile ici : les failles vivent dans les endpoints et les handlers.

La leçon spécifique de cette cible : sur un agent à outils, la surface dangereuse n'est pas le chat, c'est la console d'administration. Nos 11 attaques par l'API ont toutes réussi — parce que la sécurité était posée dans le dialogue, pas dans le code qui exécute.

Corriger, c'était donc déplacer la sécurité du chat vers le serveur :

Au passage, un durcissement que nous n'avions pas prévu : valider le rôle demandé lors d'une délégation. Un rôle inconnu doit être refusé.

Les mêmes 18 attaques, rejouées : plus aucune ne passe. Et la fonctionnalité tient — 7 contrôles de non-régression : les trois rôles fonctionnent, et le redémarrage admin avec confirmation passe bien.

20/20 porte sur les vecteurs testés, pas sur une invulnérabilité générale.

La preuve qui compte

Re-test complet relancé sans clé API, donc sans aucun modèle : 20/20, identique.

Les correctifs ne dépendent ni du fournisseur, ni du modèle, ni de sa version. Ils tiennent dans le code — précisément là où étaient les failles.

La morale

Nous avons cherché la sécurité du côté du modèle parce que c'est rassurant. Mais un agent à outils agit par ses outils, pas par ses phrases. Si votre console d'administration accepte un rôle dans le corps de la requête, si elle exécute une action irréversible sans confirmation, si elle fait confiance à un contenu ou persiste une instruction — le modèle n'y peut rien.

Sur un agent qui agit, la sécurité se juge sur ce que l'API accepte, pas sur ce que le chat raconte.
